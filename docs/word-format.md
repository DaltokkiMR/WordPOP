# 단어 파일 형식

원본 자료는 `material/`에 그대로 보관합니다. 앱이 읽는 자료는 `word_list/책-id/과별파일.json`에 저장합니다. 예를 들어 Wordmaster 47과는 `word_list/wordmaster/unit-47.json`입니다. 책 폴더 하나가 앱의 책 하나가 되고, 그 안의 JSON 파일 하나가 과 하나가 됩니다. JSON은 텍스트 데이터를 일정한 항목과 배열로 저장하는 파일 형식입니다.

앱은 완성된 JSON을 읽습니다. 원본을 외부 LLM에 전송하거나 자동으로 변환하는 기능은 포함하지 않습니다. 새 자료를 변환할 때에는 [변환용 프롬프트](convert-prompt.md)를 활용할 수 있습니다.

## 저장 예시

```json
{
  "schemaVersion": 1,
  "bookId": "my-book",
  "bookTitle": "나의 단어장",
  "unitId": "1",
  "unitTitle": "1과",
  "source": "material/my-book.md",
  "words": [
    {
      "id": "my-book-1-bank",
      "word": "bank",
      "sourceMeaning": "은행, 강둑",
      "meanings": [
        {
          "ko": "은행",
          "en": "An organization that keeps money and provides financial services.",
          "wrongEn": "A device that measures the temperature of the air."
        },
        {
          "ko": "강둑",
          "en": "The land along the edge of a river.",
          "wrongEn": "A musical piece written for one singer."
        }
      ]
    }
  ]
}
```

## 항목 설명

| 항목 | 설명 |
| --- | --- |
| `schemaVersion` | 형식 버전입니다. 현재는 숫자 `1`을 씁니다. |
| `bookId` | 책의 고유 식별자입니다. 책 폴더 이름과 같아야 합니다. |
| `bookTitle` | 앱에 표시할 책 이름입니다. 같은 책의 모든 과에서 같아야 합니다. |
| `unitId` | 책 안에서 겹치지 않는 과 식별자입니다. 숫자로 된 과 번호도 `"1"`처럼 문자열로 저장합니다. |
| `unitTitle` | 앱에 표시할 과 이름입니다. 예: `1과`. |
| `source` | 프로젝트 폴더를 기준으로 한 원본 자료 경로입니다. 원본 추적을 위해 기록합니다. |
| `words` | 원문 순서대로 넣은 단어 목록입니다. 최소 한 단어가 필요합니다. |
| `id` | 전체 단어 자료에서 겹치지 않는 단어 식별자입니다. 책·과·철자를 조합하고, 한 과에서 철자가 중복되면 번호를 덧붙입니다. |
| `word` | 원문에 적힌 영단어 또는 표현입니다. |
| `sourceMeaning` | 원문 한글 뜻을 그대로 보존하는 항목입니다. 띄어쓰기와 기호, 오타도 그대로 남깁니다. |
| `meanings` | 한 단어의 뜻쌍 목록입니다. 최소 한 쌍이 필요합니다. |
| `ko` | 해당 뜻쌍의 한글 뜻입니다. |
| `en` | 바로 앞 `ko`와 같은 뜻의 영어 정의입니다. 예문이 아니라 뜻을 설명하는 문장을 씁니다. |
| `wrongEn` | 해당 단어의 **어떤 뜻에도 해당하지 않는** 영어 정의입니다. 추가하는 일반 자료에서는 생략할 수 있습니다. 초기 Wordmaster 자료는 모든 뜻쌍에 들어 있습니다. |
| `sourceNote` | 원문 오타를 학습용 뜻에서 보완했거나, 품사·뜻이 불확실한 경우 그 이유를 설명합니다. 필요할 때 단어 항목에 추가합니다. |
| `studyNote` | 학습자가 플래시카드의 **내 노트**에 적은 메모입니다(1,000자 이하). 앱이 저장하며 AI 시험 출제에 참고합니다. 자료를 만들 때에는 넣지 않습니다. |

앱이 읽는 데 필수인 항목은 `schemaVersion`, `bookId`, `bookTitle`, `unitId`, `unitTitle`, `words`, 그리고 각 단어의 `id`, `word`, `meanings`와 각 뜻쌍의 `ko`, `en`입니다. 새 자료를 만들 때에는 원문 대조가 가능하도록 `source`와 `sourceMeaning`도 항상 기록하는 것을 권장합니다. 초기 Wordmaster 자료의 원문 경로와 뜻은 데이터 검사에서 필수로 확인합니다.

## 여러 뜻을 나누는 기준

플래시카드의 단어 전체 표시는 선택적 `studyLevel` 문자열에 저장합니다. 값은 `priority`(우선 학습, 단축키 Q), `unknown`(모름, W), `review`(복습 필요, E), `off`(끔, R) 중 하나이며, 한 단어는 이 중 한 단계만 가집니다. 강한 순서는 `priority` > `unknown` > `review` > `off`입니다.

여러 의미 중 모르는 의미만 선택한 경우에는 `unknownMeaningKeys` 배열에 해당 의미의 키를 저장합니다. 키는 앞뒤 공백을 제거한 `ko`, 구분 문자 `\u001f`, 앞뒤 공백을 제거한 `en`을 합친 문자열입니다. 의미 순서가 바뀌어도 같은 뜻을 추적하며, 이 단어에 실제로 있는 뜻만 중복 없이 저장합니다. 모르는 뜻이 하나라도 있으면 단어는 최소 `review`로 취급하고 저장하므로, `off`와 모르는 뜻이 함께 있는 파일은 `review`로 읽습니다. `priority`나 `unknown`이면 선택한 뜻은 그대로 유지합니다. 단계가 `off`가 아닌데 고른 뜻이 없으면 모든 뜻을 모르는 것으로 해석하며, 저장값은 빈 배열 그대로 둡니다. 모든 뜻을 고른 경우도 같게 해석하므로, 뜻이 하나뿐인 단어는 플래시카드에서 뜻을 따로 고르지 않습니다. 같은 철자를 여러 책·과에서 합쳐 학습할 때에는 가장 강한 단계를 보여 주며, 의미별 표시는 해당 의미가 실제로 있는 원본 단어에만 저장합니다.

학습자 노트는 선택적 `studyNote` 문자열에 저장합니다. 앞뒤 공백을 제거해 저장하고, 빈 노트를 저장하면 필드를 지웁니다. 같은 철자를 여러 책·과에서 합쳐 학습할 때에는 서로 다른 노트를 줄바꿈으로 이어 보여 주며, 노트를 고쳐 저장하면 선택한 모든 원본에 같은 내용이 저장됩니다. 원본 자료의 설명인 `sourceNote`와는 별개입니다.

예전 `studyMarks` 배열과 `studyMark` 필드도 읽을 수 있습니다. 우선순위는 `studyLevel`, `studyMarks`, `studyMark` 순입니다. `studyMarks`에 `unknown`과 `review`가 함께 있으면 모름, `review`만 있으면 복습 필요, `[]`이면 끔으로 처리하고, `studyMark`의 `unknown`은 모름, `review`와 `unsure`는 복습 필요로 처리합니다. 표시를 저장할 때 `studyLevel`로 바꾸고 예전 필드는 제거합니다. 뜻·원문 등 나머지 필드는 유지하며, 파일을 읽기만 할 때에는 변경하지 않습니다. 반복 횟수와 시험 결과는 단어장 파일과 분리해 `records/`에 저장합니다.

‘경멸하다, 멸시하다’처럼 같은 뜻의 유사 표현은 하나의 `ko`에 함께 적을 수 있습니다. ‘은행’과 ‘강둑’처럼 다른 의미는 서로 다른 뜻쌍으로 나눕니다. 명사와 동사처럼 품사가 다르면 뜻이 비슷하더라도 나누어 저장합니다. 각 뜻쌍 안에서 한글 뜻과 영어 정의가 서로 대응해야 합니다.

한글 뜻과 영어 정의를 각각 독립된 목록으로 저장하면 순서가 어긋날 수 있으므로, 항상 `{"ko": "...", "en": "..."}`처럼 함께 묶습니다. 예시의 `bank`는 단어 하나에 두 뜻을 저장한 것입니다. 같은 단어의 뜻마다 별도의 단어 항목을 만들지 않습니다.

## 오답 정의 작성 기준

`wrongEn`은 다른 개념을 설명하는 자연스러운 영어 정의로 작성합니다. `bank`의 ‘은행’ 뜻에 대한 오답으로 ‘강둑’을 사용하면 단어의 다른 뜻에는 맞으므로 사용할 수 없습니다. 정답에 `not`만 붙이거나, 품사를 어색하게 바꾸거나, 의미 없는 문장으로 만들지 않습니다. 원문에 없는 뜻이라도 그 단어의 실제 의미와 겹치면 오답으로 쓰지 않습니다.

`wrongEn`을 생략할 수 있다는 것은 잘못된 정의를 임의로 넣어도 된다는 뜻이 아닙니다. 확실한 오답을 작성하지 못했다면 생략하고, 정답인 `ko`·`en` 쌍의 정확성을 먼저 확보합니다.

## 원문 보존과 검사

원문을 고치지 않고 `sourceMeaning`에 보존합니다. 명백한 오타를 `ko`에서 보완한 경우에는 `sourceNote`에 원래 표현, 수정한 표현, 이유를 남깁니다. 뜻을 확신하기 어려울 때에는 임의로 단정하거나 새로운 의미를 추가하지 말고, 원문이 허용하는 좁은 범위의 정의와 구체적인 검토 메모를 기록합니다.

프로젝트 폴더에서 `npm run validate`를 실행하면 형식과 중복을 확인합니다. 초기 Wordmaster 25~30과, 46~50과는 각 40단어, 합계 440단어이며, 원문 철자·순서·`sourceMeaning`과 모든 `wrongEn`의 존재도 검사합니다. 초기 자료를 유지하면서 새로운 책과 과를 추가할 수 있습니다. 자동 검사는 영어 정의가 실제로 올바른지까지 판정하지 않으므로, 변환 후 뜻과 오답을 읽어 검토해야 합니다.
