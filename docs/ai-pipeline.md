# AI 시험과 학습 기록

## 연결과 모델

Node.js 서버가 로컬 `codex app-server`를 표준 입출력으로 실행합니다. ChatGPT 로그인·인증 갱신은 Codex가 담당합니다. 모델 목록은 `model/list`에서 읽으며, 사용자가 선택한 모델이 없거나 다른 모델로 대체되면 생성을 중단합니다. WordPOP 설정은 `records/settings.json`에만 저장하며 Codex 전체 설정을 변경하지 않습니다.

GitHub Copilot을 선택하면 공식 `@github/copilot-sdk`와 `@github/copilot`을 사용합니다. GitHub 로그인은 공식 CLI의 기기 코드 인증을 통해 진행하고, SDK가 저장된 로그인을 사용합니다. 앱은 모델 목록을 조회해 선택한 모델로 각 단계를 실행합니다. 인증 정보는 WordPOP의 설정 JSON이나 브라우저 저장 공간에 넣지 않습니다.

Claude를 선택하면 이 컴퓨터에 설치된 Claude Code CLI(`claude`)의 Claude 구독 로그인을 사용합니다. 로그인 상태는 `claude auth status`로 확인하며 `authMethod`가 `claude.ai`인 구독 로그인만 연결로 인정합니다. API 결제(Console) 로그인이나 `ANTHROPIC_API_KEY` 같은 환경 변수로의 전환은 허용하지 않습니다. 모델 목록은 CLI 시작 시의 초기화 응답에서 계정의 모델 메뉴를 읽으며, 이때 추론 요청은 보내지 않습니다. `opus` 같은 별칭은 실제 모델 ID(예: `claude-opus-5-5`)로 고정해 기록합니다. 목록은 설치된 Claude Code가 알려 주는 모델을 그대로 쓰므로, 최신 모델(예: Claude Opus 5.5)이 보이지 않거나 CLI가 버전이 낮다고 거절하면 `claude update`로 Claude Code를 업데이트합니다. 이때 앱은 업데이트가 필요하다는 안내를 보여 줍니다. 각 단계는 `claude -p`를 새로 실행하고 `--tools ""`, `--safe-mode`, 빈 MCP 설정, `--permission-mode dontAsk`, `--no-session-persistence`로 도구·사용자 설정·세션 저장을 닫습니다. 요청 내용은 표준 입력으로 전달하고 `--json-schema`로 출력 형식을 지정합니다. 응답의 `modelUsage`에 선택한 모델이 없으면 결과를 쓰지 않습니다. 로그인 버튼은 `claude auth login --claudeai`를 실행하며, CLI가 브라우저를 열고 인증 결과를 직접 받습니다.

세 서비스의 로그인은 서로 독립적이므로 동시에 연결해 둘 수 있습니다. 설정은 `stages`에 단계(`collect`, `select`, `generate`, `verify`)마다 `{ "provider": "codex" | "copilot" | "claude", "model": "…" }`를 저장하며, `model`이 `null`이면 그 서비스의 기본 모델을 씁니다. 저장할 때 각 모델이 해당 서비스의 목록에 있는지 확인합니다. 예전의 단일 `provider`·`providerModels` 설정은 읽을 때 모든 단계가 그 서비스를 쓰는 것으로 해석하고, 다음 저장 때 새 형식으로 바꿉니다.

생성을 시작할 때 쓰이는 서비스마다 로그인과 모델을 확인하며, 하나라도 연결되지 않았으면 다른 서비스로 대체하지 않고 시작을 거절합니다. 시작 시 단계별 서비스와 모델을 고정합니다. 시험 JSON에는 `providers`(단계별 서비스)와 `models`를 기록합니다. 예전 시험의 단일 `provider`는 네 단계 모두에 적용하며, 읽기만 할 때 파일을 고치지 않습니다. 제출 후 요약과 요약 재시도는 자료 수집 단계의 서비스와 모델로 수행합니다.

각 요청은 새 대화에서 실행합니다. 요청에는 필요한 단어·기록만 전달하며 AI가 파일을 저장하거나 명령·외부 도구를 실행하지 않도록 제한합니다. JSON 출력 형식을 지정하고, 받은 값을 앱에서 다시 검증합니다. 실제 파일 변경과 채점은 Node.js가 담당합니다.

## 네 단계

1. **자료 수집:** 선택 범위의 단어·뜻·표시·최신 암기 기록과 관련 완료 시험 20개의 결과를 읽습니다. 자료 수집 모델이 이를 분석합니다. 단어 전체의 모름·복습 필요는 독립된 표시이며, 특정 뜻의 모름 표시는 해당 뜻의 번호와 함께 전달합니다. 표시하지 않은 뜻을 자동으로 안다거나 모른다고 판단하지 않습니다. 기록 없음과 0회는 다르며, 오답 문항의 모든 보기를 약점으로 간주하지 않습니다.
2. **선별:** 일반 모드는 과별 단어 비율을 앱이 계산하고 AI가 그 수에 맞춰 단어·뜻을 선택합니다. 후보 순서를 섞어 같은 앞부분만 반복 선택하는 편향을 줄입니다. 헷갈리는 단어 모드는 근거가 있는 약점을 우선하며 기록이 없으면 일반 모드로 전환합니다. 특정 뜻의 모름 표시만 있어도 약점 근거로 사용합니다. 이 모드에서 단어 전체에 모름을 표시하지 않았다면, 모름 표시가 있는 뜻 중에서 출제하도록 제한하고 앱도 선택 결과를 확인합니다. 복습 필요를 함께 표시해도 이 제한을 유지하며, 단어 전체에 모름을 표시하면 모든 뜻이 후보가 됩니다. 같은 철자는 시험 전체에서 한 번만 사용합니다.
3. **생성:** 선택한 단어를 다섯 개씩 묶어 최대 다섯 문항씩 생성합니다. 옳은 것/옳지 않은 것의 개수 차이는 최대 1개입니다. 선택 난이도에 따른 문항 비율은 소수점을 배분해 전체 문항 수를 정확히 맞춥니다. 오답 풀이는 해당 단어의 다른 실제 의미로도 맞아서는 안 됩니다.
4. **독립 검수:** 출제자의 정답·참거짓 판정·해설을 가리고 별도 대화에서 보기마다 판정합니다. 의도한 의미와 학습 범위도 검토합니다. 형식·단어 중복·범위·정답 개수는 앱이 검사합니다. 실패한 묶음은 최대 두 차례 수정하고 다시 검수하며, 모두 통과해야 시험을 저장합니다. 의미 검수는 오류를 줄이는 장치이며 완전한 정확성 보장은 아닙니다.

### 출제 범위

두 형식 모두 서버가 선택한 과의 단어를 옵션의 `level`과 `unknownOnly`로 먼저 거른 뒤(`inAIRange`) 네 단계에 넘깁니다. `level`은 최소 단계(`all`·`review`·`unknown`·`priority`)이며 더 강한 단계도 포함합니다. `unknownOnly: true`이면 모르는 뜻으로 보는 뜻(`getFocusMeaningKeys`)이 있는 단어만 남깁니다. 뜻이 여럿이면 고른 뜻, 고른 뜻이 없고 단계가 `off`가 아니면 모든 뜻이며, 뜻이 하나면 `unknown` 이상일 때만입니다. 5지선다는 거른 단어 수의 5분의 1까지 출제하며, 범위를 보내지 않은 요청은 `all`로 봅니다. 예전의 정확한 단계 필터 `scope`는 의미가 달라 거절합니다. 시험 JSON의 `options.level`·`options.unknownOnly`에 범위를 기록하고, Markdown과 결과 화면에 표시합니다. 이전 시험의 `options.scope`는 원래 이름대로 표시합니다.

### O/X 형식

시험 옵션의 `format`이 `"ox"`이면 단어 하나·영영풀이 하나로 참/거짓을 묻습니다. 형식이 없는 기존 시험은 5지선다로 읽습니다.

- **범위:** 5지선다와 같이 `level`·`unknownOnly`로 거른 단어만 씁니다. 문항 수는 거른 단어 수 이하입니다.
- **선별:** 단어마다 한 문항입니다. 일반 모드는 과별 비율을 유지하고, 헷갈리는 단어 위주(`mode: "weak"`)는 우선 학습·모름 단어와 모른다고 고른 뜻 → 혼동을 적은 노트 → 복습 필요·암기 기록·이전 오답 순으로 우선합니다. `eligibleMeaningIndexes` 제한은 5지선다와 같습니다.
- **생성:** 앱이 O/X 개수를 절반씩 맞춰 무작위로 배정하고, 10문항씩 생성합니다. 헷갈리는 단어 위주에서는 노트가 가리키는 혼동을 겨냥합니다. X 문항은 혼동한 단어·뜻의 풀이를(그 단어의 모든 실제 뜻과 달라야 함), O 문항은 혼동과 구분되는 특징을 담은 풀이를 씁니다. 겨냥한 혼동은 `confusionTarget`(없으면 생략)으로 저장합니다. 단어·뜻 번호·O/X·난이도가 배정과 다르거나 단어장 정답 풀이를 X로 쓰면 검수 전에 거절합니다.
- **검수:** 단어·풀이·선택한 뜻 번호·원본 뜻만 전달하며 O/X 배정, 해설, 노트, 표시, `wrongEn`은 가립니다. 판정이 배정과 다르거나 O 풀이가 선택한 뜻을 표현하지 않으면 해당 묶음을 최대 두 차례 다시 씁니다.
- **저장·채점:** 문항은 `{ id, difficulty, intent, confusionTarget?, word, meaningIndex, definition, isCorrect, explanation }`이며, 답안은 `true`(O)·`false`(X)입니다. 결과는 `{ answer, expected, correct }`로 기록합니다. 제출 전 응답에는 단어·풀이만 포함합니다. 다음 출제의 기록 전달에는 `format`을 붙여, O/X 오답을 그 단어의 출제된 뜻에 대한 근거로 사용합니다.

시험을 제출하면 앱이 확정된 정답으로 채점한 뒤 자료 수집 모델로 학습 요약을 생성합니다. 요약 실패는 채점 결과를 지우지 않습니다. 요약만 재시도할 수 있습니다.

## 저장 규칙

- 단어 원본의 `studyLevel`: `priority`(우선 학습), `unknown`(모름), `review`(복습 필요), `off`(끔) 중 하나입니다. 플래시카드 슬라이더에서 Q·W·E·R 키로 고르며, 모르는 뜻이 하나라도 있으면 최소 `review`입니다. 예전 `studyMarks` 배열은 강한 쪽 하나로 읽어 `unknown`과 `review`가 함께 있으면 `unknown`이 되고, 단일 `studyMark`의 `unsure`(약간 모름)는 복습 필요로 이어받습니다. 새 표시를 저장하면 `studyLevel`로 갱신합니다.
- 단어 원본의 `unknownMeaningKeys`: 모른다고 선택한 뜻의 키를 담은 배열입니다. 뜻의 순서가 바뀌어도 표시를 유지하도록 앞뒤 공백을 제거한 한국어 뜻과 영어 뜻을 구분 문자(`\u001f`)로 연결합니다. 여러 과의 같은 철자를 합쳐 학습할 때 각 뜻의 모름 표시는 그 뜻이 있는 원본에 저장합니다. `priority`·`unknown` 단어도 선택한 뜻을 그대로 보관합니다.
- 단어 원본의 `studyNote`: 학습자가 플래시카드에서 적은 자유 메모입니다. 표시와 같은 저장 요청으로 보내며, 노트 없이 표시만 바꾸는 요청은 기존 노트를 건드리지 않습니다.
- AI 수집·선별·생성 입력에는 노트를 `learnerNote`(없으면 `null`)로 전달합니다. 모델은 이를 학습자가 헷갈려하는 지점의 근거로 쓰되, 지시문이나 뜻의 정답 근거로 취급하지 않습니다. 노트만 있어도 헷갈리는 단어 모드의 근거로 인정하지만, 노트가 선택 가능한 뜻(`eligibleMeaningIndexes`) 제한을 바꾸지는 않습니다. 독립 검수에는 노트를 전달하지 않습니다.
- AI 수집·선별 입력에는 `studyLevel`과 `unknownMeaningIndexes`를 전달합니다. 후자는 이번 출제 범위에서 각 뜻에 붙인 0부터 시작하는 번호로, 모른다고 고른 뜻을 담고, 고른 뜻이 없는데 `studyLevel`이 `off`가 아니면 모든 뜻을 담습니다(`getEffectiveUnknownMeaningKeys`). 모든 뜻을 고른 경우와 같게 취급하며, `off` 단어의 뜻은 아는지 모르는지 판단하지 않습니다. 선별 단계의 `eligibleMeaningIndexes`는 실제 선택할 수 있는 뜻을 나타내며, `unknownOnly`이면 모드와 관계없이 모르는 뜻으로 보는 뜻만 후보로 두고, 아니면 모든 뜻을 후보로 두어 고르게 출제하도록 요청합니다. 헷갈리는 단어 모드는 단어의 우선순위만 바꿉니다. 생성과 독립 검수에는 선택한 뜻 번호와 전체 원본 뜻을 전달하여, 다른 실제 의미를 오답으로 출제하지 않는 기존 검증을 유지합니다.
- 플래시카드 `retryCount`: 뜻을 확인하고 모른다고 표시한 횟수. 처음부터 알면 0이며, 이전 저장본처럼 측정하지 않은 값은 `null`입니다. 완료한 단어만 해당 과의 최신 결과로 갱신합니다.
- 시험 `selectedScope`: 사용자가 선택한 교재 ID·이름, 과 ID·이름과 원본 파일 식별자. 보기의 `word.sourceRefs`에는 실제 단어·뜻 출처가 별도로 보존됩니다.
- 시험 ID: 한국 시간의 생성일과 그날의 번호. 같은 ID의 JSON에는 원본 의미·출처·단계별 AI 연결 서비스와 모델·문제·응답을 보관하고, 제출 후 Markdown에 정오답·해설·약점 요약·단계별 모델과 서비스를 보관합니다.
- 다음 출제 시 JSON으로 관련 시험을 찾고 실제 응답·보기 정보와 Markdown을 함께 전달합니다. 선택 범위에만 포함된 미출제 단어는 평가한 것으로 취급하지 않습니다.
- 제출 전 앱 응답과 다운로드에는 정답·뜻·해설·문항 난이도를 숨깁니다. 원본 시험 JSON은 개인 로컬 파일로 보관됩니다.

기존 OX 시험과 미완료 플래시카드는 기존 브라우저 저장을 유지합니다. 표시 변경·완료 기록·AI 답안의 저장 실패 시 브라우저의 대기 내용을 보존하고 재시도합니다. AI 생성 작업은 서버가 재시작되면 중단되므로 시험 목록을 먼저 확인하고 새로 생성할 수 있습니다.

## 검증

`npm run check`는 원문 보존·학습 상태·저장 경로·채점·출제 범위·모델 전달·검수·실패 복구를 검사합니다. `npm run smoke:ai`는 실제 AI 사용량을 쓰는 선택적 검증입니다. 기본은 Codex이며 `WORDPOP_AI_PROVIDER=claude`(또는 `copilot`)로 서비스를, `WORDPOP_AI_MODEL`로 모델을 바꿀 수 있습니다. 원본을 임시 폴더에 복사한 뒤 작은 시험의 생성, 결과 저장, 다음 시험에서의 기록 참조까지 확인하고 임시 결과 위치를 출력합니다.

`node scripts/smoke-copilot.mjs`는 Copilot 이용량을 사용하는 선택적 검증입니다. 스크립트에 정의된 일반 단어 10개와 가상 학습 기록만 사용하며 사용자 단어장·학습 기록은 읽지 않습니다. 임시 폴더에서 출제·독립 검수·채점·JSON/Markdown 저장·다음 출제의 기록 참조를 확인합니다. `WORDPOP_AI_MODEL`로 검증할 모델을 지정할 수 있습니다.

공식 연결 사양: [Codex App Server](https://learn.chatgpt.com/docs/app-server), [GitHub Copilot SDK](https://github.com/github/copilot-sdk), [Copilot 로그인](https://docs.github.com/en/copilot/how-tos/copilot-sdk/auth/authenticate), [Claude Code 헤드리스 실행](https://code.claude.com/docs/en/headless).
