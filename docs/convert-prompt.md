# 원본 자료를 단어 JSON으로 바꾸는 프롬프트

아래 내용을 LLM에게 전달하고, `material/`에 보관한 자료를 함께 읽게 하거나 첨부합니다. 대괄호로 표시한 책 정보와 경로를 실제 값으로 바꾸어 사용합니다. 이 문서는 반복해서 사용할 변환 지시문이며, 앱이 외부 LLM API를 호출해 자동 변환하는 기능은 아닙니다.

원본 파일은 그대로 보존합니다. 변환 결과를 과별 JSON으로 저장한 뒤 `npm run validate`로 형식을 검사하고, 단어·뜻·영어 정의를 원본과 대조합니다. 자동 검사는 의미의 정확성을 대신하지 않습니다.

---

다음 원본 단어 자료를 WordPOP에서 사용할 과별 JSON 파일로 변환해 주세요.

- 원본 파일: `[material/원본파일명]`
- 책 식별자와 폴더 이름: `[book-id]`
- 앱에 표시할 책 이름: `[책 이름]`
- 결과 폴더: `[word_list/book-id/]`
- 변환할 과: `[원본에 있는 모든 과 또는 지정한 과]`

원본 파일은 수정하지 마세요. 표, 문장, 이미지, PDF 등 원본 형식과 관계없이 실제로 읽을 수 있는 내용만 옮겨 주세요. 읽히지 않는 단어와 뜻을 추측해서 채우지 말고, 해당 위치와 확인이 필요한 이유를 별도로 보고해 주세요. 책이나 과 구분이 모호하면 임의로 섞지 말고 확인이 필요한 부분을 알려 주세요.

각 과를 별도의 JSON 파일로 저장해 주세요. 과 번호가 1이면 파일 이름은 `unit-1.json`으로 작성해 주세요. 파일에 접근하거나 저장할 수 없는 환경에서는 파일 이름을 먼저 쓰고, 그 파일의 완전한 JSON을 따로 제공해 주세요.

파일 구조는 다음을 따라 주세요. JSON 내부에는 주석, 생략 표시, 마크다운을 넣지 마세요.

```json
{
  "schemaVersion": 1,
  "bookId": "[book-id]",
  "bookTitle": "[책 이름]",
  "unitId": "1",
  "unitTitle": "1과",
  "source": "[material/원본파일명]",
  "words": [
    {
      "id": "[book-id]-1-[단어식별자]",
      "word": "[원문 영단어]",
      "sourceMeaning": "[원문 한글 뜻을 그대로 보존]",
      "meanings": [
        {
          "ko": "[이 뜻의 한글 표현]",
          "en": "[이 뜻을 설명하는 직접 작성한 영어 정의]",
          "wrongEn": "[이 단어의 어떤 뜻에도 맞지 않는 영어 정의]"
        }
      ]
    }
  ]
}
```

다음 기준을 지켜 주세요.

1. 원문 영단어의 철자와 순서, 과 구분을 보존하고 누락하거나 임의로 추가하지 마세요. 같은 단어의 여러 의미는 한 단어 항목의 `meanings`에 넣으세요. 원본 자체에 별개의 중복 항목이 있다면 임의로 삭제하지 말고 기록해 주세요. `id`는 전체 자료에서 겹치지 않게 만들고 필요하면 순번을 붙이세요.
2. `sourceMeaning`은 원문에 적힌 한글 뜻을 띄어쓰기와 기호까지 그대로 남기세요. 학습용 `ko`에 원문의 모든 의미를 반영하세요. 뜻이 같은 한글 표현은 함께 묶되, 서로 다른 의미나 다른 품사는 별도의 뜻쌍으로 나누세요.
3. 각 `en`은 같은 항목의 `ko`만 명확하고 간결하게 설명하세요. 영어 정의는 직접 작성하고 외부 사전의 정의를 복사하지 마세요. 단어 자체를 그대로 반복해서 정의하지 마세요. 예문이나 번역이 아니라 의미를 설명하는 정의로 작성하세요. 원문에 없는 새로운 뜻은 임의로 추가하지 마세요.
4. 각 `wrongEn`은 다른 실제 개념을 설명하는 자연스러운 영어 정의로 직접 작성하세요. 정답과 비슷한 길이와 품사로 쓰되, 해당 단어의 **모든 실제 뜻**과 불일치해야 합니다. 같은 단어의 다른 뜻은 오답이 아닙니다. 단순히 `not`을 붙이거나 우스운 문장으로 만들지 마세요. 확실한 오답을 만들 수 없다면 일반 추가 자료에서는 `wrongEn`을 생략하고 그 항목을 보고하세요.
5. 명백한 오타를 학습용 `ko`에서 바로잡을 때에는 `sourceMeaning`을 그대로 유지하고, 단어의 `sourceNote`에 원래 표현·고친 표현·이유를 기록하세요. 뜻이나 품사가 불확실하면 그 불확실성과 확인할 지점을 `sourceNote`에 구체적으로 남기세요. 불확실한 해석을 검증된 사실처럼 쓰지 마세요. 정확한 뜻쌍을 만들 수 없는 항목은 완성 데이터라고 주장하지 말고 별도 확인 대상으로 보고하세요.
6. `bookId`는 저장 폴더 이름과 같게, `bookTitle`은 같은 책의 모든 과에서 같게 유지하세요. `unitId`는 문자열이고 책 안에서 중복되면 안 됩니다. `sourceNote`와 `wrongEn`을 쓰지 않을 경우에는 빈 문자열 대신 항목 자체를 생략하세요. `ko`와 `en`은 생략할 수 없습니다.
7. 저장 전에 JSON 파싱이 가능한지 확인하고, 과별 단어 수·단어 순서·원문 뜻 보존·전체 `id` 중복 여부를 대조하세요. 생성한 모든 영어 정의와 오답을 읽어 의미상 맞는지도 검토하세요. 원문에 총 단어 수가 적혀 있으면 실제 수와 비교하세요.

완료 후 저장한 파일별 단어 수와 뜻쌍 수, 원문에서 보완한 표현, 불확실하거나 추가 확인이 필요한 항목, 실제로 수행한 검사를 간단히 보고해 주세요. 파일을 저장할 수 없었거나 검사하지 못한 항목이 있다면 그 한계도 정확히 알려 주세요.
